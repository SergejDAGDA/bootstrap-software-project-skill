# Independent acceptance: new-project bootstrap v0.1.4

The bundled unit tests verify **contract text and package integrity only**. They do not prove Codex automatically discovers, invokes, or follows the skill. Use temporary disposable project directories. Keep the canonical skill repository, installed skills, real project folders, user files and external infrastructure unchanged during this review.

## Preflight

- Treat `SKILL.md` as the sole normative workflow contract. Inspect `agents/openai.yaml` only as an entrypoint: it must delegate to `SKILL.md` without any conditional owner/fallback policy. The safety reference supplies concrete checks, not competing eligibility or completion rules.

- Review the exact repository commit and the five installable skill files.
- Inventory `maintain-project-memory` and `project-documentation`. If installed, verify versions/provenance and the actual owner gates; if absent, test the documented standalone baseline without treating absence itself as an environment failure. Installed-but-unusable owners are blockers.
- Verify the user's intent and selected **temporary** target directory before any writes. No global `AGENTS.md` modification is needed for testing; its optional routing fragment can be reviewed separately.
- Separate contract adherence from automatic invocation. The latter is **NOT VERIFIED** until the skill is installed and triggered from a fresh user request in an actual Codex Desktop session.

## Additional v0.1.2 portability regressions

**Metadata regression:** in a temporary copy, add `otherwise use standalone`, `if installed and usable`, or another owner-selection condition inside `agents/openai.yaml`'s default prompt. Contract tests must fail even though the authoritative `SKILL.md` stays correct.

7. **No GitHub/no author identity:** using an isolated Git environment with no remote, account or explicit identity, a plain Prepare request must ask for a name/email and local-vs-global scope **before substantial file writes**. It must not invent a `noreply` email or mutate global configuration without separate consent. After choosing repo-local identity, a genuine first local commit succeeds.
8. **Existing identity:** explicit repo/global/conditional config or authorized author/committer environment overrides should work without a repeat prompt; missing either author or committer must not generate a false PASS, nor should an auto-guessed username@hostname.
9. **No companion skills and mixed availability:** in controlled disposable contexts, complete Prepare and Build with neither owner and independently with only one installed; record per-owner gates, honest project notes/checks/commits. Do not fabricate schema, owner installations or audits. Report standalone or mixed mode as applicable.
10. **Installed owner failure:** with an installed but unusable memory or documentation owner, expect BLOCKER/INCOMPLETE and no misleading first success commit; no silent fallback. When the user expressly requires an unavailable protocol, also stop and ask.
11. **Existing-file matrix:** check empty, concept-only with SVG and binary assets, blank clean Git root, **project-local `AGENTS.md` alone containing maintained rules**, substantive configuration alone, meaningful application source, and unrelated/sensitive files. Verify preserved bytes, correct existing-project or new-project route, selective staging and source checksums if potentially modified.

12. **Integrated memory adoption routing (v0.1.4):** On a disposable integrated Bootstrap candidate, deliberately omit the canonical Minimum WIP Continuity stop boundary or explicit Checkpoint/SESSION_LOG routing **before the completion gate**. The owner's `audit_project_memory.py <root> --adoption` may return exit code `0` while reporting `missing-review-required`: Bootstrap must classify this as **BLOCKER / INCOMPLETE**, withhold PREPARED/BUILD READY and any first commit, and route correction to the installed memory owner. Re-run the gate only after the owner restores canonical routing. Positive acceptance requires **both** `ADOPTION wip_continuity_routing=declared` and `ADOPTION checkpoint_routing=declared`, plus the normal structural audit. A pre-existing real project is a read-only negative fixture, never a target for re-bootstrap or manual repair. These checks do not demonstrate automatic skill invocation without a fresh installed-skill Desktop run.

## Required evidence

Check the *top-level* Prepare and Existing-project route definitions against the same eligibility and owner rules as the owner-specific steps and safety reference. A passing static string search alone does not establish agent behavior; regression tests must fail when these key route conditions are deliberately removed or made unconditional.

Record per scenario: input/selected root, user authorization, workflow mode, **skills actually loaded vs merely discovered**, selected platform and stated assumptions, initial and final `git status` and full HEAD, exact created/changed paths, **applicable AGENTS markers, five memory files and both adoption-routing results (when owner installed), or standalone project notes**, commands and observed exit codes, **actual owner audits or labeled native standalone checks**, Git identity provenance and chosen scope, a concise content check, and forbidden operations absent. Keep all examples synthetic and disposable. No GitHub repository creation, package publication, releases, deployment, cloud writes, or changes to the installed skills.

Report **ACCEPTED** only when all required scenarios genuinely pass. Report BLOCKER (evidenced contract failure), ENVIRONMENT (runner/tool access), IMPROVEMENT/FUTURE (nonblocking), and NOT VERIFIED (not tested) distinctly. Do not describe text-based unit tests as full integration coverage.
