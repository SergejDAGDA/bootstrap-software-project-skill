# Bootstrap Software Project

[English](README.md)

Универсальный Agent Skill для Codex, превращающий концепцию в подготовленный **новый программный проект**. Поддерживает сайты, веб-приложения, Windows/macOS/Linux программы, калькуляторы, CLI-инструменты, библиотеки, сервисы, расширения и сочетания этих типов. Навык сам определяет характер продукта и **не привязан к одному технологическому стеку**.

**Версия:** кандидат исправления `v0.1.1`, ожидает независимую приёмку и обновление локальной установки. Версия `v0.1.0` прошла ручные тесты, но реальный запуск на новой папке показал: агент может подготовить документацию и Git, не активировав координатор Bootstrap и не создав проектную память. Эта версия усиливает маршрутизацию и вводит обязательный контроль памяти перед завершением.

## Назначение

Навык координирует уже существующие возможности:

- принимает описание из Markdown-документов, текущего задания или обоих источников;
- выявляет тип продукта, целевые платформы и минимальный полезный результат;
- задаёт вопросы только при архитектурно существенной неоднозначности;
- передаёт создание `AGENTS.md` и `docs/project-memory/` навыку `maintain-project-memory` в режиме Bootstrap;
- передаёт продуктовую документацию навыку `project-documentation` в режиме init;
- в режиме Build выбирает штатный инструмент или генератор выбранного стека, готовит исходники, зависимости, `.gitignore` и реальные проверки;
- согласованно инициализирует локальный Git и создаёт первый безопасный коммит, не выполняя push или deploy.

Это **координатор**, а не замена двум специализированным навыкам. Для успешного Prepare/Build обязательны пять канонических файлов Project Memory, протокол и политики в `AGENTS.md`, успешный аудит памяти; один только аудит Product Knowledge и чистый Git не означают, что Bootstrap завершён. Если нужный навык отсутствует или не может подтверждённо работать, Bootstrap явно фиксирует ограничение, а не притворяется завершённым.

## Старт нового проекта — пример задания

Открой новый чат Codex Desktop в выбранной папке. Подставь свой путь вместо `<ПУТЬ_К_ПАПКЕ_ПРОЕКТА>`. Если в папке уже есть `CONCEPT.md` или документы MVP, они используются как исходный материал; если нет — опиши идею в самом задании. **Другой проект-референс не требуется.** В примере специально не перечислены Agent Skills и технологии.

```text
Начинаем новый самостоятельный программный проект.
Папка проекта: <ПУТЬ_К_ПАПКЕ_ПРОЕКТА>

Изучи находящиеся здесь документы концепции и MVP, если они есть.
Если их нет, моя концепция: <КРАТКОЕ_ОПИСАНИЕ_ИДЕИ>.

Для начала подготовь проект к разработке: определи тип приложения,
предложи архитектуру и границы MVP, составь поэтапный план с
проверяемыми результатами и создай необходимую постоянную документацию
и инструкции проекта. Пока не реализуй приложение.
Уточняй только существенные нерешённые вопросы, не выдавай предложения
за уже утверждённые решения.

Разрешаю локальную инициализацию Git и первый безопасный локальный
коммит в указанной новой папке. Не создавай удалённый репозиторий,
не выполняй push, публикацию, релиз и deployment. Сохрани исходные файлы.
По завершении отчитайся, что создано и проверено и какие вопросы открыты.
Не объявляй проект готовым, если обязательная подготовка не закончена.
```

Для режима Build попроси дополнительно создать минимально работающую версию и выполнить реальные проверки. Простой разговор об идее не запускает создание файлов. Автоматический выбор навыка не гарантирован: [опциональное глобальное правило](docs/OPTIONAL_GLOBAL_ROUTING.md) можно использовать **только после отдельного согласования**, без перезаписи существующего `AGENTS.md`.

## Режимы

- **Explore:** обсуждение концепции без создания файлов или Git.
- **Prepare:** концепция, MVP, решения, проектные документы, память и локальная история; исходный код приложения может отсутствовать.
- **Build:** то же плюс минимальное работающее приложение и реально исполненные проверки.
- **Existing project:** вместо повторного создания — adoption/обновление с сохранением имеющихся данных.

## Git и разрешения

**Локальный Git — стандартный результат Bootstrap** для серьёзного программного проекта, даже если GitHub никогда не будет использоваться. Установка навыка с GitHub не требует Git в папке создаваемого приложения.

Важное разграничение: разрешение на локальный `git commit` из `maintain-project-memory` **не является** разрешением на `git init`. Последнее можно один раз заранее разрешить для явно выбранных пользователем новых проектных каталогов через [опциональные глобальные инструкции](docs/OPTIONAL_GLOBAL_ROUTING.md) либо разрешить в конкретном запросе. В случайной папке или внутри чужого Git-репозитория автоматической инициализации нет. Push, публикация, CI-провайдер, Release и deployment — отдельные действия.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют структуру навыка, маршрутизацию, границы владения документацией и памятью, кроссплатформенность и правила Git. Это **не** имитация полноценного запуска Codex.

## Приёмка и регрессия

В [протоколе приёмки](docs/ACCEPTANCE.md) появился сценарий запуска **обычным запросом без названий навыков** в новом сеансе Codex Desktop. Отсутствие Project Memory при наличии коммита считается неуспешным Bootstrap. Одни контрактные тесты не доказывают автоматический запуск навыка. До объединения требуется независимая приёмка исходников; проверка автоматического обнаружения проводится после установки в новом сеансе Desktop.
