# Bootstrap Software Project

[English](README.md)

Универсальный Agent Skill для Codex, превращающий концепцию в подготовленный **новый программный проект**. Поддерживает сайты, веб-приложения, Windows/macOS/Linux программы, калькуляторы, CLI-инструменты, библиотеки, сервисы, расширения и сочетания этих типов. Навык сам определяет характер продукта и **не привязан к одному технологическому стеку**.

**Состояние:** кандидат `v0.1.0`, **не опубликован и не установлен**. Подготовлены контракт и его статические тесты; ещё необходима независимая проверка на реальном Codex Desktop в новой папке.

## Назначение

Навык координирует уже существующие возможности:

- принимает описание из Markdown-документов, текущего задания или обоих источников;
- выявляет тип продукта, целевые платформы и минимальный полезный результат;
- задаёт вопросы только при архитектурно существенной неоднозначности;
- передаёт создание `AGENTS.md` и `docs/project-memory/` навыку `maintain-project-memory` в режиме Bootstrap;
- передаёт продуктовую документацию навыку `project-documentation` в режиме init;
- в режиме Build выбирает штатный инструмент или генератор выбранного стека, готовит исходники, зависимости, `.gitignore` и реальные проверки;
- согласованно инициализирует локальный Git и создаёт первый безопасный коммит, не выполняя push или deploy.

Это **координатор**, а не замена двум специализированным навыкам. Если нужный навык отсутствует или не может подтверждённо работать, Bootstrap явно фиксирует ограничение, а не притворяется завершённым.

## Режимы

- **Explore:** обсуждение концепции без создания файлов или Git.
- **Prepare:** концепция, MVP, решения, проектные документы, память и локальная история; исходный код приложения может отсутствовать.
- **Build:** то же плюс минимальное работающее приложение и реально исполненные проверки.
- **Existing project:** вместо повторного создания — adoption/обновление с сохранением имеющихся данных.

Устанавливаемый пакет — только `skills/bootstrap-software-project/`, остальные файлы относятся к репозиторию навыка.

## Git и разрешения

**Локальный Git — стандартный результат Bootstrap** для серьёзного программного проекта, даже если GitHub никогда не будет использоваться. Установка навыка с GitHub не требует Git в папке создаваемого приложения.

Важное разграничение: разрешение на локальный `git commit` из `maintain-project-memory` **не является** разрешением на `git init`. Последнее можно один раз заранее разрешить для явно выбранных пользователем новых проектных каталогов через [опциональные глобальные инструкции](docs/OPTIONAL_GLOBAL_ROUTING.md) либо разрешить в конкретном запросе. В случайной папке или внутри чужого Git-репозитория автоматической инициализации нет. Push, публикация, CI-провайдер, Release и deployment — отдельные действия.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют структуру навыка, маршрутизацию, границы владения документацией и памятью, кроссплатформенность и правила Git. Это **не** имитация полноценного запуска Codex.

## Следующая приёмка

Нужны испытания в отдельных временных каталогах Codex Desktop: новая папка с Markdown-концепцией (Prepare), новая папка с описанием в задании (Build), обычное обсуждение идеи (без записи), и проверка недеструктивного поведения в уже существующем проекте. Проверить файлы, проверки запуска, локальный Git, отсутствие публикации и независимый review перед установкой.
