# Bootstrap Software Project

[English](README.md)

Универсальный Agent Skill для Codex, превращающий концепцию в подготовленный **новый программный проект**. Поддерживает сайты, веб-приложения, Windows/macOS/Linux программы, калькуляторы, CLI-инструменты, библиотеки, сервисы, расширения и сочетания этих типов. Навык сам определяет характер продукта и **не привязан к одному технологическому стеку**.

**Версия исходного пакета навыка:** `0.1.5`. Создаваемый `AGENTS.md` теперь содержит постоянные правила, а не временные утверждения о PREPARE/BUILD и ожидаемом Git-коммите. Версии исходников, опубликованного релиза и установленной копии необходимо проверять отдельно.

**Имя репозитория и идентификатор навыка — разные сущности:** GitHub-репозиторий — `SergejDAGDA/bootstrap-software-project-skill`, но установленный Agent Skill сохранит имя `bootstrap-software-project` (каталог `skills/bootstrap-software-project/`, поле `name` и вызов `$bootstrap-software-project`). Суффикс `-skill` относится **только** к репозиторию. Поддержка других сред, кроме проверенного Codex Desktop, не заявляется как протестированная.

## Релизы и обновление

Постоянный адрес последнего стабильного выпуска GitHub: `https://github.com/SergejDAGDA/bootstrap-software-project-skill/releases/latest`. Каждый выпуск должен указывать на проверенный точный commit через тег `vX.Y.Z` и публиковаться как обычный GitHub Release с пометкой **Latest**. Предварительные версии (beta/RC) не заменяют стабильный канал. После публикации нужно проверить тег и пометку Latest. Подвижная ветка `main` не является идентификатором релиза.

Для ручной установки или обновления берите каталог `skills/bootstrap-software-project/` из проверенного стабильного релиза, а не случайное состояние `main`, и используйте поддерживаемый способ установки Codex Skills в пользовательский каталог навыков. Сверьте маркер `VERSION` с тегом. Сохраните существующую авторскую конфигурацию перед заменой, не перезаписывайте её автоматически. После обновления откройте новый сеанс Codex Desktop и проверьте доступность навыка. Пометка `Latest` сама по себе не устанавливает обновления.

## Назначение

Навык координирует уже существующие возможности:

- принимает описание из Markdown-документов, текущего задания или обоих источников;
- выявляет тип продукта, целевые платформы и минимальный полезный результат;
- задаёт вопросы только при архитектурно существенной неоднозначности;
- передаёт создание `AGENTS.md` и `docs/project-memory/` навыку `maintain-project-memory` в режиме Bootstrap;
- передаёт продуктовую документацию навыку `project-documentation` в режиме init;
- в режиме Build выбирает штатный инструмент или генератор выбранного стека, готовит исходники, зависимости, `.gitignore` и реальные проверки;
- согласованно инициализирует локальный Git и создаёт первый безопасный коммит, не выполняя push или deploy.

Это **координатор**, а не замена двум специализированным навыкам. **Единственный нормативный контракт — устанавливаемый `SKILL.md`; `agents/openai.yaml` только запускает его и не задаёт собственные правила fallback.** При установленном `maintain-project-memory` успешный Prepare/Build требует пять канонических файлов, markers в `AGENTS.md`, структурный owner-аудит и два значения маршрутизации `--adoption`, равные `declared`; при установленном `project-documentation` требуется его аудит. Неисправный установленный owner — **BLOCKER**, не повод скрытно перейти на другой режим. Если дополнительных навыков **нет**, Bootstrap создаёт минимальные обычные документы и выполняет нативные проверки в **автономном режиме**, без имитации чужих схем и аудитов. Явно запрошенный отсутствующий протокол по-прежнему блокирует завершение.

## Старт нового проекта — пример задания

Открой новый чат Codex Desktop в выбранной папке. Подставь свой путь вместо `<ПУТЬ_К_ПАПКЕ_ПРОЕКТА>`. Если в папке уже есть `CONCEPT.md` или документы MVP, они используются как исходный материал; если нет — опиши идею в самом задании. **Другой проект-референс не требуется.** В примере специально не перечислены Agent Skills и технологии.

```text
Начинаем новый самостоятельный программный проект.
Папка проекта: <ПУТЬ_К_ПАПКЕ_ПРОЕКТА>

Изучи находящиеся здесь документы концепции и MVP, если они есть.
Если их нет, моя концепция: <КРАТКОЕ_ОПИСАНИЕ_ИДЕИ>.

Для начала подготовь проект к разработке: определи тип приложения,
предложи архитектуру и границы MVP, составь поэтапный план с
проверяемыми результатами и создай необходимую постоянную документацию
и инструкции проекта. Пока не реализуй приложение.
Уточняй только существенные нерешённые вопросы, не выдавай предложения
за уже утверждённые решения.

Разрешаю локальную инициализацию Git и первый безопасный локальный
коммит в указанной новой папке. Не создавай удалённый репозиторий,
не выполняй push, публикацию, релиз и deployment. Сохрани исходные файлы.
По завершении отчитайся, что создано и проверено и какие вопросы открыты.
Не объявляй проект готовым, если обязательная подготовка не закончена.
```

Для режима Build попроси дополнительно создать минимально работающую версию и выполнить реальные проверки. Простой разговор об идее не запускает создание файлов. Автоматический выбор навыка не гарантирован: [опциональное глобальное правило](docs/OPTIONAL_GLOBAL_ROUTING.md) можно использовать **только после отдельного согласования**, без перезаписи существующего `AGENTS.md`.

## Режимы

- **Explore:** обсуждение концепции без создания файлов или Git.
- **Prepare:** концепция, MVP, решения, документы и локальная история; установленным owner-навыкам принадлежат их канонические артефакты, для отсутствующих применяется автономный минимум. Если доступен только один owner, режим смешанный.
- **Build:** то же плюс минимальное работающее приложение и реально исполненные проверки.
- **Existing project:** код приложения, существенная конфигурация, сохранённые правила проекта (включая проектный `AGENTS.md`) или Project Memory означают adoption/обновление без повторного Bootstrap.

## Git identity без GitHub

Для коммита нужны имя и email автора и коммитера. Bootstrap заранее проверяет эффективную конфигурацию Git и разрешённые переменные окружения, но не требует GitHub, не ищет персональные данные в профилях и не выдумывает `noreply`-адрес. Если явно установленной идентичности нет, Codex задаёт **один промежуточный вопрос**: какие имя/email использовать и записывать ли их только для проекта или глобально. Глобальная запись требует отдельного согласия. Email — метаданные коммита, не данные входа; действующий почтовый ящик необязателен. До разрешения вопроса индекс и файлы сохраняются, а коммит не выполняется.

## Папка с рабочими файлами

Пустая папка и папка только с концепцией, требованиями или исходными SVG/изображениями пригодны для Bootstrap. Сначала выполняется инвентаризация, исходники сохраняются. Программный код, существующая проектная память или существенная конфигурация переводят запрос в **existing project**. Непонятные, конфиденциальные, бинарные, лицензионно спорные файлы нельзя бездумно менять или добавлять в первый коммит.

## Git и разрешения

**Локальный Git — стандартный результат Bootstrap** для серьёзного программного проекта, даже если GitHub никогда не будет использоваться. Установка навыка с GitHub не требует Git в папке создаваемого приложения.

Важное разграничение: разрешение на локальный `git commit` из `maintain-project-memory` **не является** разрешением на `git init`. Последнее можно один раз заранее разрешить для явно выбранных пользователем новых проектных каталогов через [опциональные глобальные инструкции](docs/OPTIONAL_GLOBAL_ROUTING.md) либо разрешить в конкретном запросе. В случайной папке или внутри чужого Git-репозитория автоматической инициализации нет. Push, публикация, CI-провайдер, Release и deployment — отдельные действия.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют структуру навыка, маршрутизацию, границы владения документацией и памятью, кроссплатформенность и правила Git. Это **не** имитация полноценного запуска Codex.

## Приёмка и регрессия

В [протоколе приёмки](docs/ACCEPTANCE.md) появился сценарий запуска **обычным запросом без названий навыков** в новом сеансе Codex Desktop. При **установленном владельце Project Memory** её отсутствие при наличии коммита означает неуспешный Bootstrap. Автономный режим имеет отдельные критерии. Одни контрактные тесты не доказывают автоматический запуск навыка. До объединения требуется независимая приёмка исходников; проверка автоматического обнаружения проводится после установки в новом сеансе Desktop.
